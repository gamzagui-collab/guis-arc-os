# GUI's Arc 구현

## 사용하지 않는 경우

- 원인 분석만 요청받았거나 요구가 아직 확정되지 않았을 때
- 검증·배포·패키징만 수행할 때

## 먼저 읽기

1. `AGENTS.md`
2. `VERSION.md`
3. `AIOS/PROJECT_STATE.md`
4. `DEVELOPMENT_RULES.md`
5. 요청 기능의 최신 계약 문서와 직접 관련 테스트

## 절차

1. 요청과 수정 예상 파일, 화면·Worker·DB·배포 영향을 선언한다.
2. 관련 파일만 읽고 기존 계약과 현재 동작을 확인한다.
3. 요구를 충족하는 최소 수정만 적용한다.
4. 기존 데이터·API·권한 계약을 유지하고 필요한 경우에만 영향 근거를 기록한다.
5. 실제 렌더·함수·이벤트 등 변경 성격에 맞는 관련 테스트를 추가하거나 갱신한다.
6. 직접 관련 테스트를 실행하고 실패 원인을 수정한다.
7. 버전·문서·패키징 필요 여부를 공식 규칙으로 판단한다.

## 금지사항

- 요청하지 않은 구조 변경·리팩터링·새 기능
- Mock을 운영 기능처럼 추가하거나 보고
- 명시적 필요 없는 DB·인증·권한·R2·Provider 변경
- 사용자 승인 없는 Production 변경

## 완료 조건

- 요구 동작이 실제 코드에 연결되어 있다.
- 관련 테스트가 통과하고 영향 범위가 확인되었다.
- 수행하지 않은 검증과 배포를 완료로 보고하지 않는다.

## 결과 보고

사용자가 확인할 동작, 수정 파일, 데이터·API·DB 영향, 관련 테스트, 제한과 다음 안전한 단계 순서로 보고한다.

## 액션 피드백 구현

- 비동기 액션에는 pending·success·error 상태, 중복 실행 차단, 데이터 갱신과 상태 보존을 구현한다.
- 공통 액션 피드백 유틸리티가 있으면 재사용하고 업무별 문구는 해당 화면에서 정의한다.

## 목적
검토·승인된 요구를 관련 파일만 수정해 구현한다.
## 사용 조건
요구와 변경 범위가 명확하고 실제 구현이 필요할 때 사용한다.
## 먼저 읽을 문서
Required file: `AGENTS.md`
Required file: `DEVELOPMENT_RULES.md`
Required file: `VERSION.md`
Required file: `AIOS/PROJECT_STATE.md`
## 예상 문제·부작용·충돌
기존 API·권한·데이터·상태 머신과 회귀를 확인한다.
## 입력
확정 요구, 관련 계약, 코드와 테스트.
## 변경 허용 범위
요청 기능과 직접 관련된 코드·테스트·문서만 수정한다.
## 테스트 및 검증
직접 테스트 후 필요한 회귀를 실행한다.
## 결과 보고 형식
사용자 동작, 수정 파일, 영향, 테스트, 제한 순서로 보고한다.
## NOT_EXECUTED 기준
배포·Browser·원격 DB를 실행하지 않았으면 완료로 간주하지 않는다.
