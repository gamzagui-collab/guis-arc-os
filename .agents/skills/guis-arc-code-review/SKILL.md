# 목적
변경 코드의 실제 결함과 회귀 위험을 우선순위와 근거로 찾는다.

## 사용 조건
- 구현 diff 또는 지정 코드의 품질·회귀 검토 요청에 사용한다.

## 사용하지 않는 경우
- 구현 전 경계 설계나 Root Cause 재현 조사에는 사용하지 않는다.

## 먼저 읽을 문서
Required file: `AGENTS.md`
Required file: `DEVELOPMENT_RULES.md`
Required file: `VERSION.md`
Required file: `AIOS/PROJECT_STATE.md`

## 예상 문제·부작용·충돌
Null, 오류 분기, 권한, Revision, Idempotency, 상태 보존과 과도한 결합을 확인한다.

## 입력
변경 파일, 관련 계약, 테스트와 재현 가능한 증거.

## 절차
기준본 확인 → 변경 범위 확인 → 동작 경로 추적 → 결함·회귀 분류 → 최소 수정 제안 → 검증 공백 보고.

## 변경 허용 범위
기본은 읽기 전용이다. 명시된 수정 요청이 있으면 동작 보존 범위의 최소 수정만 허용한다.

## 금지사항
요청 밖 리팩터링, 기능 축소, 스타일 취향만의 지적, Production 변경을 금지한다.

## 테스트 및 검증
결함마다 재현 또는 코드 근거를 제시하고 관련 테스트 결과를 연결한다.

## 완료 조건
실행 가능한 발견 사항이 심각도와 파일 위치를 포함한다.

## 결과 보고 형식
발견 사항 우선, 질문·가정, 변경 요약, 미검증 순서로 보고한다.

## NOT_EXECUTED 기준
실행하지 않은 테스트와 Browser 검증을 코드 검토 PASS로 대체하지 않는다.
