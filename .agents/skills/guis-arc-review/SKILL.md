# GUI's Arc 검토

## 사용하지 않는 경우

- 사용자가 명확한 구현을 요청해 바로 수정해야 할 때
- 검증 실행이나 패키징·배포만 수행할 때

## 먼저 읽기

1. `AGENTS.md`
2. `VERSION.md`
3. `AIOS/PROJECT_STATE.md`
4. `DEVELOPMENT_RULES.md`
5. 요청과 직접 관련된 최신 계약 문서

## 절차

1. 사용자 요청을 한 문장으로 확정한다.
2. 관련 코드·테스트·계약만 찾는다.
3. 현재 동작을 재현하거나 읽기 전용 근거로 확인한다.
4. 오류라면 Route → Stack Trace → 예외 → Service → Query → Migration → Null → 권한 순서를 필요 범위에서 확인한다.
5. Root Cause와 변경 필요 범위를 분리한다.
6. 화면·API·Worker·DB·R2·배포 영향과 영향 없는 범위를 기록한다.
7. 오래된 문서 충돌은 현재 사실로 사용하지 말고 근거와 함께 표시한다.

## 금지사항

- 요청하지 않은 전체 저장소 감사 또는 자동 코드 수정
- 무관한 기능 제안·리팩터링
- 과거 AIOS·Handoff를 현재 사실로 단정
- 원인을 확인하지 않은 추측 수정

## 완료 조건

- 현재 동작과 Root Cause가 근거로 구분되어 있다.
- 최소 변경 범위와 영향 없음 범위가 명확하다.
- 미확인 사항은 `UNKNOWN` 또는 `NOT_EXECUTED`로 남긴다.

## 결과 보고

사용자 요청, 확인된 현재 동작, Root Cause, 변경 필요 범위, 영향 없음 범위, 문서 충돌, 구현 권고 순서로 보고한다.

## 액션 피드백 검토

- 변경 대상 사용자 액션의 처리 중·성공·실패 피드백 누락과 중복 실행 위험을 먼저 확인한다.

## 목적
요청의 현재 동작·위험·충돌과 최소 범위를 구현 전에 종합 검토한다.
## 사용 조건
전체 요청의 진입 검토와 필요한 전문 Skill 선택이 필요할 때 사용한다.
## 먼저 읽을 문서
Required file: `AGENTS.md`
Required file: `DEVELOPMENT_RULES.md`
Required file: `VERSION.md`
Required file: `AIOS/PROJECT_STATE.md`
## 예상 문제·부작용·충돌
오래된 계약, 범위 확대, 데이터·권한·배포 혼동을 확인한다.
## 입력
사용자 요청, 현재 기준본, 관련 계약과 근거.
## 변경 허용 범위
기본은 읽기 전용이며 명시 승인된 최소 문서 수정만 허용한다.
## 테스트 및 검증
확인한 근거와 실행 결과를 구분한다.
## 결과 보고 형식
현재 동작, Root Cause, 위험, 최소 범위, 미검증 순서로 보고한다.
## NOT_EXECUTED 기준
재현·테스트·원격 검증을 실행하지 않았으면 각각 표시한다.
