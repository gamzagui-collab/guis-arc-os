# PC Issue Management Dashboard 계약

## 적용 범위

- 버전: v0.24.0
- 적용 화면: 761px 이상 PC Issue 목록
- 모바일 Issue 목록과 Photo Viewer는 기존 계약을 유지한다.
- Today, R2, Issue 상태 머신은 변경하지 않는다.

## 목록과 조회

- 목록은 현재 권한과 현장 범위 안의 이슈만 반환한다.
- 상태, 확정 부서, canonical 공종, 미배정, 검색 조건은 함께 적용할 수 있다.
- 부서 집계 기준은 확정 부서이며 확정되지 않은 이슈는 미분류로 취급한다.
- 원본 사진은 목록에서 조회하지 않고 작은 썸네일만 사용한다.
- 한 화면에는 최대 50건을 조회하며 행별 추가 조회를 만들지 않는다.

## 선택

- PC 관리 권한 사용자는 개별 선택, 현재 페이지 전체 선택·해제, Shift 범위 선택을 사용할 수 있다.
- 전체 선택 체크박스는 일부 선택 시 indeterminate 상태를 표시한다.
- 필터를 다시 조회하면 현재 결과 밖 선택은 제거된다.
- 변경 실패 시 선택을 유지하고 성공 시 선택을 해제한다.

## 일괄 변경 API

- 경로: `POST /api/v1/issues/bulk`
- 최대 50건이며 각 항목은 `id`와 `revision`을 포함한다.
- 변경하지 않는 필드는 생략하고 명시적 `null`은 해제로 처리한다.
- 지원 필드는 업체, 공종, 담당자, 확정 부서다.
- 업체 변경으로 기존 공종이나 담당자가 무효가 되면 요청의 명시적 정리 옵션 없이는 거부한다.
- 공종은 선택 업체의 활성 현장 계약 공종, 담당자는 선택 업체의 활성 현장 사용자여야 한다.
- SITE 범위와 `issue.assign` 권한 및 Issue Board EDIT 이상을 요구한다.

## 동시성·감사

- 모든 선택 항목과 Revision을 변경 전에 검증한다.
- 핵심 변경, 배정 이력, Idempotency, 이슈별 Audit, Batch Audit은 하나의 D1 batch로 기록한다.
- 동일 Idempotency-Key와 동일 payload 재호출은 기존 Batch ID를 반환한다.
- 공종이 변경된 이슈는 Construction Engine 추천을 다시 평가하며 기존 확정 부서는 보존한다.
- 성공 응답은 Batch ID, 성공 건수, 이슈 ID, 다음 Revision, 변경 필드, 재평가 건수를 포함한다.

## 배포

- v0.24.0 구현 작업에서는 신규 Migration을 추가하지 않는다.
- Integration과 Production은 배포하지 않는다.

## v0.24.1 사용자 액션 피드백

- 목록 조회와 필터·검색 갱신 중에는 조회 버튼을 비활성화하고 “이슈 목록을 불러오고 있습니다...”를 표시한다.
- 일괄 변경 중에는 대상 건수를 포함한 문구, Spinner, `aria-busy`를 표시하고 실행·닫기를 차단한다.
- 성공하면 서버 응답 건수를 안내하고 목록을 다시 조회한 뒤 변경된 행을 잠시 강조하며 선택을 해제한다.
- 실패하면 Dialog 입력과 선택을 유지하고 다시 시도할 수 있게 한다.
- Revision 충돌은 별도 한국어 문구와 목록 새로고침 버튼을 제공하며 자동으로 덮어쓰지 않는다.
- 공통 액션 피드백 유틸리티는 시각적 Toast와 `role="status"`·`role="alert"` 기반 Inline 상태를 함께 제공한다.
- Bulk API, DB Schema, Migration, R2, 모바일 Photo Viewer, Today는 변경하지 않는다.

## v0.24.2 일괄 변경 후보와 정렬 Hotfix

- Dialog를 열 때 선택 이슈의 업체 구성을 평가한다. 같은 업체면 해당 업체의 활성 현장 계약 공종, 서로 다른 업체면 모든 업체에 공통인 canonical 공종의 교집합만 표시한다.
- 업체 미배정 이슈가 포함되면 업체를 먼저 선택하도록 안내하며 공종 지정을 제한한다.
- Dialog에서 새 업체를 선택하면 해당 업체의 계약 공종과 활성 현장 담당자를 즉시 다시 계산한다. “변경하지 않음” 복귀 시 원래 선택 구성을 재평가한다.
- 후보는 기존 `GET /api/v1/issues/options`의 `companies[].trades[].id`와 `displayName`, `companies[].assignees[].id`와 `display_name`을 사용한다. 비활성·다른 현장·권한 밖 데이터는 Worker의 기존 조회 계약에서 제외한다.
- 후보 로딩·없음·실패를 한국어 Inline 상태로 표시하고 관련 Select에 `disabled`, `aria-busy`, `aria-describedby`를 적용한다. 갱신 요청 토큰으로 이전 응답이 최신 선택을 덮는 것을 막는다.
- 공종 해제는 후보 없음과 혼동하지 않도록 별도 체크로 제공한다.
- 종속 값 정리 옵션은 input과 문장을 하나의 Grid label로 묶으며 전체 문장 클릭, Space 조작, 두 줄 줄바꿈과 focus 표시를 유지한다.
- Dialog 필드는 공통 Grid와 `width:100%`, `min-width:0`을 사용한다. API, DB, Migration, R2, Today, Construction Engine Rule은 변경하지 않는다.

## v0.24.3 직영·미배정 구분

- 목록 필터와 업체 표시는 협력업체·직영·미배정을 명시적으로 구분한다.
- 단건 및 일괄 변경에서 직영을 선택하면 원도급사의 활성 현장 사용자와 현재 현장 활성 공종만 후보로 표시한다.
- 직영 전환 시 기존 협력업체 ID는 남기지 않으며, 호환되지 않는 담당자·공종은 사용자의 명시적 정리 선택 없이는 변경을 거부한다.
