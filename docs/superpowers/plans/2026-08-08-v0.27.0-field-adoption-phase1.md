# GUI's Arc v0.27.0 Field Adoption Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Today 원본 작업에서 기존 Issue를 안전하게 생성하고 실제 담당자가 네 가지 최소 응답을 append-only로 남기게 한다.

**Architecture:** Construction provider가 bounded source item refs를 만들고 전용 resolver가 stale revision을 보수적으로 해석한다. Issue 생성은 source를 optional relation으로 batch 저장하며 재식별 실패 시 일반 Issue로 계속 저장한다. 담당 응답 권한은 UI와 Worker가 공유하는 순수 함수로 계산하고 최신값은 issue별 `response_revision`으로 결정한다.

**Tech Stack:** Cloudflare Workers JavaScript, D1/SQLite migration, 정적 ES modules, Node `node:test`, 기존 API·권한·idempotency·Audit 패턴.

## Global Constraints

- 기준 Commit `5a04ee280c5b72fb578bc5f0bc247d4fda3daa15`, 목표 버전 `v0.27.0`.
- v0.26.0 Voice 코드와 Voice FSM/Debug/Review UI를 병합하지 않는다.
- `construction-work-N`을 영구 identity로 사용하지 않고 Work Package Entity를 만들지 않는다.
- source 문제는 Issue·사진·위치·내용 등록을 실패시키지 않는다.
- 담당 응답은 네 상태와 관리자 최소 표시만 구현한다.
- 기한 변경·응답 승인·자동 재배정·자동 알림·책임 점수·응답 통계 Dashboard·추가 상태를 구현하지 않는다.
- Integration Migration·Worker·Pages는 각각 별도 승인 전 실행하지 않고 Production은 변경하지 않는다.
