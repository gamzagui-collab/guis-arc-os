# 현재 현장 공종 사전 운영

## 적용 범위

- 이 사전은 현재 현장 전용 `SITE` 데이터다.
- 다른 현장 표현이나 범용 건설 공종을 임의로 추가하지 않는다.
- 실제 공사일보에서 확인된 표현만 추가한다.
- 사용자가 화면에서 직접 사전을 수정하는 관리 UI는 제공하지 않는다.

## 공식 데이터 위치

- 표준 공종과 별칭: `worker/modules/construction/trade-data/site-trade-dictionary.js`
- 충돌 관계: `worker/modules/construction/trade-data/site-trade-conflicts.js`
- 무결성 검증과 통합 export: `worker/modules/construction/trade-data/index.js`

분석 Corpus와 원본 공사일보는 공식 사전 데이터가 아니며 제품 ZIP에 포함하지 않는다.

## 별칭 추가 절차

1. 실제 공사일보 원문에서 새로운 표현을 확인한다.
2. 기존 표준 공종과 같은 의미인지 확인한다.
3. 다른 공종의 기존 별칭과 정규화 결과가 충돌하지 않는지 확인한다.
4. 확정된 관계만 `status: "CONFIRMED"`로 추가한다.
5. 판단이 끝나지 않았다면 `status: "REVIEW_REQUIRED"`로 기록한다. 이 상태는 자동 매칭에 사용되지 않는다.
6. 데이터 검증, 매칭 단위 테스트, Parser 및 Today 테스트를 추가한다.

예시:

```js
{value:"전기통신 설비공",status:"CONFIRMED"}
```

기존 표준 공종은 `ELECTRICAL_COMMUNICATION`이며, 추가 위치는 `site-trade-dictionary.js`다.

## 신규 표준 공종 추가 절차

표현이 기존 공종과 실제로 다른 공종일 때만 표준 ID, 한글 표시명, 분류, `SITE` 범위, 별칭, 핵심어를 모두 작성한다. 기존 데이터와 ID·별칭 중복이 없어야 하며 관련 충돌 관계와 테스트를 함께 추가한다.

## 충돌 관계 추가 절차

두 표준 공종을 자동 연결하면 안 된다는 현장 근거가 있을 때만 `site-trade-conflicts.js`에 양쪽 표준 ID와 한국어 사유를 추가한다. 자기 자신 충돌과 동일 관계 중복은 허용하지 않는다.

`기계설비공 ↔ 전기설비공`은 전기설비공이 현재 공식 표준 공종으로 등록되지 않았으므로 별도 표준 ID를 추측하지 않는다. 기존의 원문 조건 검사를 유지하며, 실제 독립 공종으로 확인될 때 공식 공종과 충돌 데이터로 이전한다.

## 코드 수정이 필요한 경우

사전·별칭·충돌 데이터만 추가할 때는 매칭 알고리즘을 수정하지 않는다. 점수, 후보 우선순위, 복합 공종 해석 또는 출력행 배정 정책 자체가 바뀌는 경우에만 `trade-matcher.js` 변경과 별도 회귀 검증이 필요하다.
